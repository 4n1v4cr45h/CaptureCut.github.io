============================================================
2. ИСХОДНЫЙ КОД CRACKME.C
============================================================

#include <stdio.h>
#include <string.h>

int main(void) {
    char password[64];

    printf("Enter password: ");

    if (fgets(password, sizeof(password), stdin) == NULL) {
        return 1;
    }

    password[strcspn(password, "\n")] = '\0';

    if (strcmp(password, "s4kh4l1n_RE") == 0) {
        puts("Access granted!");
    } else {
        puts("Access denied!");
    }

    return 0;
}

============================================================
3. НАЗНАЧЕНИЕ ПРОГРАММЫ
============================================================

1. Создаёт локальный буфер password размером 64 байта.
2. Выводит приглашение Enter password:.
3. Читает строку с помощью fgets.
4. Если чтение не удалось, возвращает код 1.
5. Удаляет символ новой строки через strcspn.
6. Сравнивает введённую строку с "s4kh4l1n_RE" через strcmp.
7. Если строки совпадают, выводит Access granted!.
8. Иначе выводит Access denied!.
9. При обычном завершении возвращает код 0.

Это локальная учебная программа, созданная для практики анализа бинарников.

============================================================
4. ПРОВЕРКА БИНАРНИКА
============================================================

Команды:

file ./crackme
strings -n 5 ./crackme
gdb -q ./crackme

Наблюдения:
- file определил ELF 64-bit для x86-64.
- Бинарник использует PIE.
- Бинарник динамически связан.
- В бинарнике присутствует debug_info.
- Бинарник не stripped.
- strings -n 5 показал строку s4kh4l1n_RE, строки Access granted! и Access denied!, а также имена динамических символов и отладочные данные.

PIE:
- Position Independent Executable.
- Адреса загрузки программы могут меняться между запусками.
- GDB показывает фактические адреса текущего запуска.

DYNAMIC LINKING:
- Внешние функции, например strcmp, fgets и puts, вызываются через динамическую компоновку.
- Имена вида strcmp@plt относятся к Procedure Linkage Table (PLT), используемой при вызове динамически связываемых функций.

============================================================
5. ОСНОВНЫЕ КОМАНДЫ GDB
============================================================

Запуск:
gdb -q ./crackme

Поставить точку останова на main:
break main

Поставить точку останова на смещение +108 от main:
break *main+108

Запустить программу:
run

Продолжить выполнение до следующей точки останова:
continue

Выполнить одну машинную инструкцию:
nexti

Показать ассемблер main:
disassemble main

Показать текущую инструкцию:
x/i $pc

Показать строку по адресу в rdi:
x/s $rdi

Показать строку по адресу в rsi:
x/s $rsi

Показать регистры:
info registers eax
info registers rdi rsi
info registers eflags

Найти сведения о strcmp:
info functions strcmp

Завершить текущий процесс внутри отладчика:
kill

ВАЖНО:
В GDB вводить каждую команду отдельно. Если вставить несколько строк команд как одну строку, GDB может попытаться разобрать их как единое выражение и выдать синтаксическую ошибку.

6. КЛЮЧЕВОЙ ФРАГМЕНТ ДИЗАССЕМБЛЕРА
============================================================

Из вывода disassemble main:

0x00005555555551e5 <+108>: call   0x555555555070 <strcmp@plt>
0x00005555555551ea <+113>: test   %eax,%eax
0x00005555555551ec <+115>: jne    0x5555555551ff <main+134>
0x00005555555551ee <+117>: lea    0xe2e(%rip),%rax
0x00005555555551f5 <+124>: mov    %rax,%rdi
0x00005555555551f8 <+127>: call   0x555555555030 <puts@plt>
0x00005555555551fd <+132>: jmp    0x55555555520e <main+149>
0x00005555555551ff <+134>: lea    0xe2d(%rip),%rax
0x0000555555555206 <+141>: mov    %rax,%rdi
0x0000555555555209 <+144>: call   0x555555555030 <puts@plt>
0x000055555555520e <+149>: mov    $0x0,%eax
0x0000555555555213 <+154>: leave
0x0000555555555214 <+155>: ret

Пояснения:
- call strcmp@plt вызывает strcmp.
- Возвращаемое значение strcmp находится в eax.
- test %eax,%eax проверяет результат и устанавливает флаги процессора.
- jne выполняет переход, если ZF = 0.
- Если strcmp вернул 0, test устанавливает ZF = 1, поэтому jne не выполняется.
- Если strcmp вернул ненулевое значение, ZF = 0, поэтому jne переходит к main+134.
- main+117 — ветка Access granted!.
- main+134 — ветка Access denied!.
- После успешной ветки jmp переходит к общему завершению функции.

Примечание:
Адреса могут измениться при другой сборке или другом запуске PIE-бинарника. Ориентироваться следует на текущий вывод GDB, символы и смещения.

============================================================
7. АРГУМЕНТЫ ФУНКЦИИ И РЕГИСТРЫ
============================================================

На x86-64 Linux при использовании System V AMD64 ABI первые шесть целочисленных или указательных аргументов передаются через:
1. rdi
2. rsi
3. rdx
4. rcx
5. r8
6. r9

В эксперименте перед strcmp:
- rdi указывал на введённый пароль.
- rsi указывал на эталонную строку "s4kh4l1n_RE".

Команды:
info registers rdi rsi
x/s $rdi
x/s $rsi

Наблюдение с неправильным паролем:
x/s $rdi
0x7fffffffdce0: "wrong_password"

x/s $rsi
0x555555556017: "s4kh4l1n_RE"

После выполнения call strcmp:
info registers eax

Для wrong_password:
eax = 0x4

Для s4kh4l1n_RE:
eax = 0x0

Интерпретация:
- strcmp возвращает 0 при равенстве строк.
- Ненулевой результат означает, что строки различаются.
- Конкретное ненулевое значение зависит от различия между строками и не является универсальным признаком ошибки.

============================================================
10. ЧАСТЫЕ ОШИБКИ И ЗАМЕЧАНИЯ
============================================================

Ошибка:
Ввести несколько команд GDB подряд одной вставкой, после чего получить:
Syntax error in expression
или
No symbol "x" in current context.

Решение:
Вводить каждую команду отдельно и проверять вывод перед следующей.

Наблюдение:
После nexti значение $pc указывает на следующую инструкцию, которая будет выполнена.

Наблюдение:
eflags, показанный до выполнения test, может ещё не отражать результат strcmp. test обновляет флаги; затем условный переход использует эти флаги.

Наблюдение:
Изменение eax после выполнения test не обязательно изменит уже установленные флаги. Для экспериментов с условными переходами нужно учитывать порядок инструкций и состояние флагов.
